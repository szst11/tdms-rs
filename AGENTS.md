# AGENTS.md

## Commands (CI gate on `main`)

Run all three before finishing; CI (`cargo clippy ... -D warnings`) treats warnings as errors:

- `cargo fmt --all -- --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo test --all-features`

## Tests

- Two named targets declared in `Cargo.toml`: `cargo test --test golden` (corpus fixtures) and `cargo test --test integration`. Use these to iterate on a single suite; `cargo test --all-features` runs everything.
- Cargo auto-discovers any `*.rs` you drop at the top of `tests/` as an extra integration-test target (e.g. `tests/string_buffers.rs`); the real entrypoints live in `tests/golden_tests/mod.rs` and `tests/integration_tests/mod.rs` subdirs.
- Golden tests open every `.tdms` under `tests/fixtures/tdms_corpus/` and compare against a sibling `.json`. Timestamp channel data is intentionally **not** compared.
- Fixtures are generated by Python scripts in `tools/` (deps in `requirements.txt`, installed via `uv`). Regenerate from `tests/fixtures/` with `uv run --with-requirements ../../requirements.txt python ../../tools/generate_corpus.py` then `../../tools/generate_json.py`, and verify with `validate_json.py`, after format/behavior changes. The scripts use a relative `CORPUS_DIR`, so they must run with `tests/fixtures/` as the working directory.
- Integration tests write scratch files to `tests/output/` and delete them; `.gitignore` does **not** ignore that dir, so don't commit new files there. Because opens may generate a `.tdms_index` companion, cleanup must remove both the `.tdms` and `_index` files (see `tests/integration_tests/common.rs`).

## Architecture

- `src/api/` holds the public reader/writer API, re-exported from `src/lib.rs` (`TdmsFile`/`TdmsGroup`/`TdmsChannel`, `OpenOptions`, `TdmsWriter`/`TdmsWriterOptions`/`WriterGroup`/`WriterChannel`).
- `src/format/` is low-level segment/metadata parsing; `src/format/index.rs` holds the `.tdms_index` serializer used by both reader and writer (`TDSh` lead-ins, raw-data offsets resolved against the data-file layout); `src/io/ext.rs` contains little-endian I/O helpers.
- `src/model/` holds data types and the in-memory index (IndexMap).
- Reader: metadata indexed eagerly at `open()`, channel data is lazy and read into caller-provided buffers. A sibling `<file>.tdms_index` is used for the metadata index when present (generated on the fly if missing — see `create_index_if_missing`); the data file is opened lazily only for channel reads.
- Writer: staged single-segment writes; file is flushed and closed on drop (RAII), with optional explicit `flush()`. Reader/writer lifetime coupling matters — `WriterGroup`/`WriterChannel` borrow from their parent.
- `src/bin_disabled/` is legacy and excluded from the crate; do not add binaries there.
- `docs/ARCHITECTURE.md` and `docs/API.md` are the canonical deep-dive docs for the design and public API.

## Constraints

- MSRV is Rust 1.70.0, edition 2021 — avoid syntax/APIs newer than 1.70.
- Little-Endian TDMS only.
- No unit tests in `src/`; all correctness testing lives in `tests/`.

## Benchmarking

- The crate declares a `benchmark` binary (`[[bin]]` in `Cargo.toml`); the full suite is driven by `python benchmark/run.py` and expects Windows `diskspd` on `PATH`.
